# getexo.app

A fast static website for Exo Launcher and Exo Cinema. Source pages are generated by `src/pages.js`; legal pages remain hand-written in `public/`.

## Build and test

In `site/`, run `npm ci`, `npm run build`, and `npm test`.
The build uses Sharp to encode the seven existing 16:9 pictures into responsive AVIFs, hashes CSS/font/JS assets, rewrites page references, and writes security headers. Existing Cinema media lives in `public/cinema-assets/`. The look reuses the Geist typeface, quiet hairlines, dark surfaces and restrained accent from `design/`.

The build also fetches the three apps' changelogs from the existing update service. Those addresses and the installed apps' update protocol are intentionally unchanged. Changelog routes use the existing service binding and cached/static fallbacks.

## Releases

**Edit only `src/releases.js`** for each app's repository, release tag, asset, version, byte size and SHA-256. Installer links use GitHub's tag-pinned `releases/download/<tag>/<asset>` form so the installer matches the displayed version and checksum even after a newer release. The current tags are `v3.26.0` for Launcher and `v1.5.1` for Cinema. Release-history links use `/releases`; the generic latest-release link uses `/releases/latest`.

Launcher links use UhhErix/Exo-Launcher; Cinema links use UhhErix/Exo-Cinema. Each has its own source and release-history link. `/download/launcher` and `/download/cinema` issue 302 redirects, including through the www Worker. Metadata routes read the same constant, never update manifests. The sizes/checksums are documented in the app repositories' RELEASES.md.

## Pages

`/`, `/cinema`, `/privacy`, `/license`, `/legal/earlier-apps`, `/404.html`, and `/{launcher,cinema,browser}/changelog`.

## Local preview and deployment

`node preview.mjs` serves built files and download/API routes at http://127.0.0.1:8787. It is a local preview, not a production server.

Cloudflare serves `public/` as Workers Static Assets. `workers/exo-site/wrangler.toml` deploys it: it runs `src/worker.js` through `workers/exo-site/src/worker.js`, which adds the source-archive routes. `workers/exo-www` redirects ordinary www paths to the apex. Download logic is shared with the static build so deployment entrypoints cannot disagree.

Deployment requires the owner's approval and configured bindings in Wrangler. No deployment is performed by build or tests. See `../workers/README.md` for the imported service inventory.
